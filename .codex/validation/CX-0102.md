## Adapter and Flag Evidence

- `src/services/workflowDefinitionCompatibility.ts` defines a bounded read-only interface: source, versions, roles, transitions, source reference, and validation only. It has no execute, persistence, Supabase, route, guard, or checklist mutation API.
- `LegacyWorkflowDefinitionProvider` delegates reads and validation. Its default delegate reports the current `roleCodes` and explicitly leaves transitions with the existing distributed services rather than duplicating business logic.
- `V25WorkflowDefinitionProvider` accepts a validated V1.8.0/V2.5.0 snapshot, copies and deeply freezes role/transition reads, and rejects invalid snapshots.
- `createWorkflowDefinitionCompatibility` separates default Legacy, validation-only, explicit V2.5, and kill-switch behavior. Explicit activation failure is never silently reported as successful V2.5 activation.

- `App.tsx` does not import the compatibility layer, so all current users and routes remain on the existing path.
