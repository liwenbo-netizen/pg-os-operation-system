## Summary

The canonical Workflow Machine is now loaded from the single tracked source at `docs/PG_OS_Workflow_Machine_V2.5.0_Codex_Ready_20260731.yaml`. `scripts/workflowMachineLoader.mjs` derives the source path from `import.meta.url`, so it does not depend on a developer-machine absolute path and works on Windows and CI.

The loader uses a deliberately bounded, non-executing YAML subset parser because the repository has no declared YAML dependency. It supports the source document's mappings, block lists, scalar values, and named anchor/alias references, while rejecting custom tags, flow collections, tabs, unknown aliases, duplicate mapping keys, excessive nesting, and oversized documents. The loaded machine is deep-frozen.

It validates V1.8.0 / V2.5.0 versions, all required registries, roles, node-stage mappings, transition references, guided-flow components, task identities, dependency existence, dependency cycles, and Wave order. It does not execute transitions, guards, checklists, audits, APIs, or user-visible workflow behavior.
